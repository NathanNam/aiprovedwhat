AX09 (outside OpenAI’s math catalogue), November 2026

Faltings’ theorem, all in Lean?

Axiom Math says it has the first complete, machine-verified proof of Faltings’ theorem: curves of genus two or more have only finitely many rational points. The statement matches an outside benchmark problem. The code was written by AI agents, has not yet been reviewed by people, and rests on Axiom’s AI-written Stacks library.

The claim, in plain words

This is AX09. Here is a curve: y² = x⁵ − x + 1. We want points where x and y are both fractions. Some are easy. When x is zero, one, or minus one, y is plus or minus one. When x is eight, the right side is 32,761, which is 181². And one surprise: x equals 7/9, with y equals 173/243. That makes ten points. Our own search through more than 2 million fractions finds nothing else. So is the list complete? A famous theorem says the list must be finite. It does not say where it ends.

Why finite? The answer is one number, the genus. Let x and y be complex numbers, and the curve becomes a surface. The genus counts its holes. Genus zero, like the circle, can have infinitely many rational points: one for every Pythagorean triple, such as (3/5, 4/5). Genus one, like y² = x³ − 2. Start at the point (3, 5). The tangent line there meets the curve again, at a new rational point, 129/100. Repeat, and the points never run out, but they get complicated fast: for P, 2P, 3P and 4P, the numerators have 1, 3, 6, then 10 digits, and 38 by 8P. Our curve has genus two. In 1922, Louis Mordell asked whether every curve of genus two or more has only finitely many rational points. In 1983, Gerd Faltings proved it, for curves over any number field, and won the Fields Medal. For example, for each n from four on, xⁿ + yⁿ = 1 has only finitely many solutions in fractions.

Axiom did not follow Faltings’ original proof. It followed a second route: Paul Vojta’s proof from around 1990, soon made much more elementary by Enrico Bombieri. The curve sits inside a larger object, its Jacobian, where the rational points form a lattice and a height measures their length. Group the points by direction, into finitely many narrow cones. Inside one cone, two forces act. Mumford’s gap principle pushes points apart: each large point is at least about twice as long as the one before. Vojta’s inequality pulls them together: beyond a certain size, one point cannot be too much longer than another. Points that must keep doubling, but cannot grow too far apart, can only be finitely many. A separate count handles the small ones. The proof says the list is finite, and can even bound its length. In general, it does not tell you how to find every point.

On November 12, 2026, Axiom Math announced what it calls the first complete, machine-verified proof of Faltings’ theorem. The repository, AxiomMath/Mordell, had been created two days earlier, with a single commit. Its main Lean theorem is the full statement: a smooth, projective, geometrically integral curve over a number field, of genus at least two, has finitely many rational points. By our count, the library has 432 Lean files and about 124,000 lines, about 111,000 of them not blank, which is close to the post’s roughly 110,000. Our text search finds no sorry and no axiom declaration. The README says Lean’s kernel checks every proof, using only Lean’s three standard axioms. This is a known theorem, formalized. There is no new mathematics.

What it doesn’t claim

Is the statement right? That is the first thing to check in any formalization. Here there is outside help. Junyan Xu wrote this theorem as a problem for the LeanEval benchmark, published in August, using Mathlib alone, with its own definitions of places and genus. Axiom’s README says that exact statement is proved, word for word, and our own text comparison finds every piece of it in Axiom’s file, in order, and a GitHub user reports that the statements print the same in both settings. That makes the statement much harder to get subtly wrong. The benchmark’s leaderboard, though, lists no solution yet. And what is not claimed: no new theorem, not Faltings’ original proof, and no way to list all the points. It is not in Mathlib either. In 2024, the number theorist Michael Stoll set the goal of getting a proof of the Mordell conjecture into Mathlib, by this same route. This library lives outside it.

No new theorem: Faltings proved it in 1983, and Bombieri’s simpler version of Vojta’s proof dates from 1990. The library does not give a way to find all the rational points of a curve, and it is not part of Mathlib.

Where it stands

Released by Axiom
Repository created November 10, 2026 (Pacific; November 11 UTC), with one commit, 82a30cb (“The Mordell conjecture in Lean”, by Ashvin A. Swaminathan); blog post on November 12, signed “Axiom”. The development history is not public.
Published machine checks
None from Axiom: no GitHub CI runs, no comparator file, no build log. The README says Lean’s kernel checks every proof and shows Axiom’s own #print axioms output (only propext, Classical.choice, Quot.sound).
Human review of the Lean
Not yet. The README: “about 430 modules written by AI agents”; “the code has not yet been reviewed by humans”. It does not name the AI model. The blog post names no people and does not mention AI. The 336 Stacks modules it imports directly are all from StacksFrontier, which Axiom’s Stacks metadata says “has not yet had human review”.
Independent check
Partial, none complete, as of November 14, 2026: issue #1 (November 13 UTC) reports a cold build of 179 modules (169 Stacks, 10 Mordell) without a Lean error before it was stopped, and asks for build files; a downstream project reports a from-scratch build of the 12,769 modules it uses, in about five and a half hours. No expert reaction found.
Peer reviewed
No (there is no paper).
Statement matches an outside benchmark
The README says the library proves the LeanEval problem “faltings” (statement by Junyan Xu, August 2026, from Mathlib alone) verbatim; our text comparison finds all 31 pieces of it in Axiom’s file, in order. The leaderboard lists no solution yet (data of November 14).
Lean library, by Axiom
Lean v4.35.0, Mathlib 56a0058 and Axiom’s Stacks library at c496df0 (lakefile); no sorry and no axiom declarations (our text grep). Not built or run by us.

If it holds, one of the landmark theorems of twentieth-century number theory is now checked by Lean’s kernel, from a statement written by someone outside Axiom, on top of millions of lines of Axiom’s Stacks code, mostly written by AI, that people have not yet reviewed. See AX08, AX07, AX06 and AX01.

The checks

  1. What has been checked? The repository has no continuous integration runs, no comparator file and no published build log. The axiom list in the README is Axiom’s own output. Any other checks so far come from outside. Right after the post, a GitHub user opened an issue: their cold build compiled 179 modules without a Lean error before they stopped it, and they asked Axiom for build files to check the rest. Another project reports a from-scratch build of the parts it uses, 12,769 modules, in about five and a half hours. Neither is a full independent check of the main theorem yet.
  2. Who wrote it? The README says the library’s roughly 430 modules were written by AI agents, and that the code has not yet been reviewed by humans. It does not name the AI model. The blog post is signed simply Axiom: it names no contributors, and it does not mention AI at all. The single commit is by Ashvin Swaminathan. As with AX07, the two documents describe the same work differently.
  3. What it sits on. It matters even more here. The library uses Mathlib, on Lean v4.35.0, and Axiom’s Stacks library from AX06, pinned to a commit made 52 minutes before this one. The post says the Stacks modules it builds on hold roughly 6.4 million lines, against about 110,000 for the proof itself. By our count, all 336 Stacks modules it imports directly come from StacksFrontier, the part that Axiom’s own metadata says has not yet had human review. About 500 tags link Lean declarations to items of Bombieri’s paper and its background.

The numbers in the video

  • Ours: y² = x⁵ − x + 1 (genus 2) has the points x = −1, 0, 1 (y = ±1), x = 8 (32,761 = 181²) and x = 7/9 (y = ±173/243): ten points, plus one at infinity. Our search through 2,158,483 fractions (denominators up to 289, numerators up to 100,000) finds nothing else; we do not claim the list is complete.
  • From Axiom’s post: the circle’s (3/5, 4/5); on y² = x³ − 2 the tangent at (3, 5) meets the curve again at (129/100, 383/1000). Ours: the numerators of x(nP) have 1, 3, 6, 10, 15, 21, 29, 38 digits for n = 1 to 8 (the post: 38 digits by 8P).
  • Ours: the repository at 82a30cb has 432 Lean files and 124,110 lines (110,808 not blank; the post says roughly 110,000), 506 @[faltings] tags, and 336 directly imported Stacks modules, all StacksFrontier; our text grep finds no sorry, admit, native_decide or axiom declaration.
  • From Axiom’s post: roughly 6,400,000 lines of Stacks library modules underneath; the Stacks commit it pins (c496df0) was made 52 minutes before the Mordell commit.
